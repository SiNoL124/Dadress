## ۱. مقدمه

### ۱.۱ هدف سند

هدف این سند، معرفی چشم‌انداز پروژه دادرس، بیان مسئله‌ای که پروژه قصد حل آن را دارد، معرفی کاربران و ذی‌نفعان، تعیین محدوده نسخه اولیه و مشخص‌کردن اهداف کلی محصول است. این سند مبنایی برای تحلیل نیازمندی‌ها، طراحی و پیاده‌سازی سامانه خواهد بود.

### ۱.۲ معرفی محصول

دادرس یک سامانه آنلاین برای کمک به افرادی است که به خدمات حقوقی نیاز دارند. کاربران می‌توانند موضوع مشکل حقوقی خود را ثبت کنند و بر اساس اطلاعات واردشده، وکلای مرتبط با موضوع را مشاهده و با یکدیگر مقایسه کنند. همچنین امکان مشاهده اطلاعات حرفه‌ای و درخواست مشاوره از وکیل در نظر گرفته می‌شود.

### ۱.۳ محدوده سند

این سند چشم‌انداز کلی محصول و قابلیت‌های مورد انتظار نسخه اولیه را مشخص می‌کند. جزئیات کامل نیازمندی‌ها، طراحی پایگاه داده و پیاده‌سازی فنی در مراحل بعدی پروژه تهیه خواهند شد.

### ۱.۴ اصطلاحات

| اصطلاح | توضیح |
|---|---|
| دادرس | سامانه معرفی و مقایسه وکلای مرتبط با مسائل حقوقی |
| کاربر | فردی که برای یافتن خدمات حقوقی از سامانه استفاده می‌کند |
| وکیل | متخصص حقوقی که اطلاعات حرفه‌ای او در سامانه نمایش داده می‌شود |
| تطبیق | فرایند پیشنهاد وکلا بر اساس موضوع و اطلاعات ثبت‌شده |
| نسخه اولیه | نخستین نسخه قابل استفاده از محصول یا MVP |

## ۲. چشم‌انداز محصول

### ۲.۱ بیانیه چشم‌انداز

هدف دادرس فراهم‌کردن راهی ساده، شفاف و قابل دسترس برای یافتن و مقایسه وکلای مرتبط با نیازهای حقوقی کاربران است؛ به‌گونه‌ای که افراد بتوانند با آگاهی بیشتری گزینه‌های موجود را بررسی کرده و برای دریافت مشاوره اقدام کنند.

### ۲.۲ اهداف اصلی

- ساده‌سازی فرایند جست‌وجوی وکیل.
- پیشنهاد وکلای مرتبط با موضوع حقوقی کاربر.
- فراهم‌کردن امکان مقایسه اطلاعات حرفه‌ای وکلا.
- کاهش سردرگمی کاربران هنگام انتخاب خدمات حقوقی.
- ایجاد بستری برای ثبت درخواست مشاوره.
- طراحی سامانه‌ای قابل توسعه و کاربرپسند.

### ۲.۳ ارزش پیشنهادی

دادرس اطلاعات مرتبط با نیاز حقوقی کاربر را در یک محیط واحد گردآوری می‌کند و به او کمک می‌کند گزینه‌های موجود را راحت‌تر بررسی کند. سامانه با ارائه اطلاعات شفاف و امکان مقایسه، فرایند اولیه یافتن وکیل را ساده‌تر می‌سازد.

---

## ۳. مسئله و فرصت

### ۳.۱ بیان مسئله

افرادی که با یک مسئله حقوقی روبه‌رو می‌شوند، ممکن است ندانند به چه تخصصی نیاز دارند یا چگونه وکیل مناسبی پیدا کنند. پراکندگی اطلاعات، دشواری بررسی سوابق حرفه‌ای و نبود امکان مقایسه منظم می‌تواند انتخاب را زمان‌بر و پیچیده کند.

### ۳.۲ راهکار پیشنهادی

دادرس به کاربران امکان می‌دهد موضوع مسئله خود را ثبت کنند، فهرستی از وکلای مرتبط دریافت کنند، اطلاعات قابل ارائه هر وکیل را بررسی کنند و گزینه‌های مناسب را با هم مقایسه کنند. سپس می‌توانند درخواست مشاوره ارسال کنند.

### ۳.۳ فرضیات پروژه

- کاربران به دنبال راهی ساده برای یافتن وکیل هستند.
- موضوع پرونده و تخصص وکیل در فرایند انتخاب اهمیت دارد.
- اطلاعات حرفه‌ای و قابل بررسی به تصمیم‌گیری آگاهانه کمک می‌کند.
- کاربران از طریق یک سامانه آنلاین می‌توانند گزینه‌های موجود را راحت‌تر مقایسه کنند.

## ۴. کاربران و ذی‌نفعان

| ذی‌نفع | نیاز یا انتظار |
|---|---|
| متقاضی خدمات حقوقی | یافتن وکیل مرتبط و مقایسه گزینه‌ها |
| وکیل | معرفی تخصص و سوابق حرفه‌ای و دریافت درخواست مشاوره |
| مدیر سامانه | مدیریت کاربران، اطلاعات وکلا و محتوای سامانه |
| تیم توسعه | پیاده‌سازی نیازمندی‌ها و نگهداری سامانه |
| نهادهای مرتبط با اعتبار حرفه‌ای | امکان بررسی و تأیید اطلاعات حرفه‌ای، در صورت فراهم‌بودن دسترسی قانونی |

### ۴.۱ شخصیت‌های نمونه کاربران

شخصیت اول: متقاضی خدمات حقوقی

- هدف: یافتن وکیل متناسب با موضوع مشکل.
- نیاز: مشاهده تخصص، سوابق و اطلاعات تماس یا مشاوره.
- چالش: دشواری بررسی و مقایسه گزینه‌های متعدد.

شخصیت دوم: وکیل

- هدف: معرفی حرفه‌ای خدمات و تخصص خود.
- نیاز: ثبت اطلاعات صحیح و دریافت درخواست‌های مرتبط.
- چالش: دسترسی به مخاطبانی که به تخصص او نیاز دارند.

شخصیت سوم: مدیر سامانه

- هدف: حفظ کیفیت و صحت اطلاعات سامانه.
- نیاز: مدیریت حساب‌ها، بررسی گزارش‌ها و به‌روزرسانی اطلاعات.
- چالش: جلوگیری از انتشار اطلاعات نادرست یا ناقص.

### ۵.۳ موارد خارج از محدوده نسخه اولیه

- ارائه نظر حقوقی قطعی و خودکار توسط سامانه.
- تضمین نتیجه پرونده یا موفقیت کاربر در مراجع قضایی.
- رسیدگی کامل آنلاین به تمام مراحل پرونده حقوقی.
- اتصال به درگاه‌های بانکی واقعی و تسویهٔ مالی واقعی (در نسخهٔ اولیه از درگاه آزمایشی Sandbox استفاده می‌شود).
- استفاده از هوش مصنوعی پیشرفته برای تحلیل اسناد حقوقی.
- تماس صوتی یا تصویری درون‌برنامه‌ای (چت متنی خصوصی در محدوده است).
- اپلیکیشن موبایل بومی (نسخهٔ اولیه فقط وب‌سایت واکنش‌گرا است).

### ۵.۴ محدودیت‌ها و وابستگی‌ها

- صحت پیشنهادها به کیفیت اطلاعات ثبت‌شده وابسته است.
- تأیید اطلاعات حرفه‌ای وکلا ممکن است به منابع معتبر و مجوزهای لازم نیاز داشته باشد.
- زمان و امکانات تیم توسعه محدود است؛ بنابراین قابلیت‌ها باید اولویت‌بندی شوند.
- جمع‌آوری و نگهداری اطلاعات باید مطابق قوانین و الزامات مربوط به حریم خصوصی انجام شود.

## ۸. رویکرد توسعه

### ۸.۱ روش پیشنهادی

توسعه پروژه به‌صورت مرحله‌ای انجام می‌شود. ابتدا نیازمندی‌های اصلی مشخص می‌شوند، سپس طراحی اولیه صورت می‌گیرد و قابلیت‌های ضروری پیاده‌سازی و آزمایش می‌شوند. بازخورد کاربران آزمایشی برای بهبود نسخه اولیه استفاده خواهد شد.

### ۸.۲ فناوری‌های پیشنهادی

فناوری‌های پیشنهادی (جزئیات و دلایل در سند معماری):

| لایه | فناوری |
| ---- | ------ |
| رابط کاربری | React + Vite + Tailwind CSS |
| سرور | Node.js + Express |
| پایگاه داده | PostgreSQL + Prisma |
| احراز هویت | JWT + bcrypt |
| پرداخت | درگاه آزمایشی (Sandbox) |
| چت | Socket.IO |
| مدیریت پروژه | GitHub Projects (Scrum) |

### ۸.۳ شرایط تکمیل قابلیت

یک قابلیت زمانی تکمیل‌شده محسوب می‌شود که:
- نیازمندی آن مشخص شده باشد.
- پیاده‌سازی آن با نیازمندی توافق‌شده مطابقت داشته باشد.
- مسیرهای اصلی عملکرد آن آزمایش شده باشند.
- خطاهای مهم شناخته‌شده برطرف شده باشند.
- مستندات مرتبط به‌روزرسانی شده باشند.
